# مسیرهای محصول

## مسیر اصلی موجود

```mermaid
flowchart TD
 A[ورود به ترب‌یار] --> B{مدل مشخص است؟}
 B -->|بله| C[جستجوی مدل]
 B -->|خیر| D[دسته، کاربرد و بودجه]
 D --> C
 C --> E[کارت‌های محصول و فیلترها]
 E --> F[مقایسهٔ حداکثر سه مدل]
 F --> G[انتخاب یک مدل]
 G --> H[آفرها و فروشگاه‌های یکتا]
 H --> I[قیمت، فاصله، زمان و اعتبار]
 I --> J[متن استعلام و یادداشت شخصی]
 J --> K{پاسخ و شرایط مناسب است؟}
 K -->|طبق پیگیری کاربر| L[ذخیره در برنامهٔ خرید]
 K -->|بسته یا بی‌پاسخ| M[کنارگذاشتن فروشگاه]
 M --> N{جایگزین منطبق هست؟}
 N -->|بله| I
 N -->|خیر| O[تغییر شرط یا مدل با انتخاب کاربر]
 O --> E
 L --> P[طبقه و واحد، نقشه و مراجعه]
```

در این نمودار «پاسخ مناسب» گزارش کاربر است، نه تأیید خودکار فروشگاه. نسخهٔ موجود، تماس واقعی انجام نمی‌دهد.

## چرخهٔ تأیید پیشنهادی — هنوز پیاده نشده

```mermaid
stateDiagram-v2
 [*] --> Unknown
 Unknown --> Pending: شماره معتبر و درخواست استعلام
 Pending --> Unanswered: بی پاسخ یا خطا
 Pending --> Verified: پاسخ معتبر و دارای منبع
 Pending --> Unavailable: اعلام عدم موجودی
 Verified --> Expired: پایان مهلت اعتبار
 Expired --> Pending: استعلام دوباره
 Unanswered --> Pending: تلاش مجدد با سیاست محدود
 Unavailable --> [*]: انتخاب فروشگاه جایگزین
```

قیمت، موجودی، ساعت و شرایط پرداخت باید وضعیت‌های مستقل داشته باشند. تأیید قیمت نباید موجودی را هم تأیید کند. اعتبار پاسخ باید به تنوع دقیق محصول و فروشگاه محدود باشد. یادداشت شخصی کاربر مستقیماً وارد وضعیت Verified نمی‌شود.

## ساختار فنی موجود

```mermaid
flowchart LR
 CSV[CSVهای رسمی] --> Import[تبدیل و بررسی روابط]
 Import --> Data[JSON فشرده و قطعه بندی شده]
 Data --> Browser[رابط RTL و محاسبهٔ محلی]
 Browser --> Local[برنامه و یادداشت در مرورگر]
 Browser --> Node[API اختیاری Node]
 Node --> Retrieval[بازیابی از همان دیتاست]
 Retrieval --> Model[مدل سازگار در صورت تنظیم دسترسی]
 Node --> Adapter[adapter تماس در صورت تنظیم دسترسی]
```

خروجی static، مسیرهای Node را اجرا نمی‌کند. adapter تماس فعلی فقط درخواست را ارسال می‌کند؛ دریافت و تصدیق نتیجه و ذخیرهٔ تأیید هنوز وجود ندارد.
