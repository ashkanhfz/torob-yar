# جستجوی ایندکس‌شده

نسخهٔ عمومی از Elasticsearch خصوصی لیارا برای جستجو و از Inverted Index داخلی برای ادامهٔ کار هنگام قطعی استفاده می‌کند. مهلت درخواست خارجی ۱٫۵ ثانیه است؛ بعد از خطا، تلاش مجدد ۳۰ ثانیه عقب می‌افتد. پاسخ‌های موفق ۳۰ ثانیه با سقف ۶۴ کلید کش می‌شوند و درخواست‌های یکسان هم‌زمان ادغام می‌شوند. جزئیات استقرار و هزینه در [راهنمای لیارا](ELASTICSEARCH-LIARA.fa.md) آمده است.

هر صفحهٔ رابط ۲۴ نتیجه می‌گیرد. API با `offset` و `nextOffset` صفحه‌بندی می‌کند و مرتب‌سازی شناسه، ترتیب نتایج هم‌امتیاز را ثابت نگه می‌دارد. اگر موتور در میانهٔ صفحه‌بندی عوض شود، رابط نتایج را از صفحهٔ اول دوباره می‌گیرد تا دو ترتیب متفاوت با هم ترکیب نشوند.

Elasticsearch روی پیشوند واژه‌های نرمال‌شده جستجو می‌کند و همهٔ واژه‌های ورودی باید تطبیق داشته باشند. ایندکس داخلی تطبیق زیررشته را هم پشتیبانی می‌کند؛ بنابراین ترتیب و تعداد نتایج دو موتور الزاماً یکسان نیست. نتیجهٔ خالی Elasticsearch، خطا یا عبور از پنجرهٔ ۱۰هزار نتیجه به ایندکس داخلی برمی‌گردد. قیمت نامشخص صفر تومان محسوب نمی‌شود و در مرتب‌سازی ارزان‌ترین، آخر قرار می‌گیرد.

## Elasticsearch محلی

```sh
bash scripts/elastic-local.sh start
ELASTICSEARCH_URL=http://127.0.0.1:9201 npm run index:elastic
ELASTICSEARCH_URL=http://127.0.0.1:9201 OSRM_BASE_URL=http://127.0.0.1:5001 PORT=3103 npm start
```

Docker باید در دسترس باشد. سرویس `9.5.5` با digest ثابت، پلن Basic، سقف ۱٫۵ گیگابایت حافظه و دو CPU اجرا می‌شود. شماره پورت ۹۲۰۱ فقط روی loopback است. احراز هویت این نمونهٔ محلی خاموش است؛ آن را روی اینترنت منتشر نکنید. نسخهٔ عمومی باید به سرویس دارای احراز هویت و شبکهٔ خصوصی متصل شود. قابلیت‌های ML و دانلود GeoIP فعال نیستند. داده در volume مستقل `torob-elastic-data` باقی می‌ماند. توقف: `bash scripts/elastic-local.sh stop`.

۲۲۵٬۹۰۳ محصول واقعی دیتاست نسخهٔ ۱۶ وارد ایندکس محلی شدند. واردکننده دسته‌های ۵۰۰تایی می‌فرستد؛ refresh در زمان واردکردن متوقف و پس از پایان فعال می‌شود. شمارش اسناد پیش از جابه‌جایی اتمیک alias بررسی می‌شود؛ ایندکس قبلی برای بازگشت حفظ می‌شود. فقط نام محصول، دسته، شناسه، قیمت و شمارهٔ shard وارد Elasticsearch می‌شوند، نه گزارش‌های خصوصی کاربران.

برای سرویس موجود، `ELASTICSEARCH_URL` و `ELASTICSEARCH_USERNAME` و `ELASTICSEARCH_PASSWORD` یا `ELASTICSEARCH_API_KEY` را فقط در محیط سرور تنظیم کنید. نقش runtime فقط مجوز خواندن دارد؛ واردکننده به حساب جداگانه با مجوز ساخت ایندکس و تعویض alias نیاز دارد. راه‌اندازی محلی، سرویس پولی جدیدی در Liara ایجاد نمی‌کند.

منبع راه‌اندازی: [مستندات رسمی Docker در Elastic](https://www.elastic.co/docs/deploy-manage/deploy/self-managed/install-elasticsearch-docker-basic).
