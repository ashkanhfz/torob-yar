# Elasticsearch در لیارا

Elasticsearch جدا از برنامه وب اجرا می‌شود؛ ایندکس معکوس داخلی همچنان همراه هر انتشار ساخته می‌شود و هنگام قطع ارتباط با Elasticsearch مسیر جایگزین جست‌وجو است.

## سرویس فعال

- نام دیتابیس: `torob-search-1023`
- نسخه: Elasticsearch `8.11.1`
- پلن: `medium-g2` با بسته `basic`، یک گیگابایت حافظه، یک CPU و ۱۰ گیگابایت دیسک.
- شبکه: همان شبکه خصوصی برنامه `torob-yar-next-1023`؛ شبکه عمومی دیتابیس غیرفعال است.
- نشانی داخلی: `http://torob-search-1023:9200`
- ایندکس: یک shard و بدون replica؛ alias ثابت `torob-products` به نسخه کامل کاتالوگ اشاره می‌کند.

قیمت خوانده‌شده از API حساب در ۲۳ اکتبر ۲۰۲۶، مجموع منابع و بسته پایه، حدود **۱٬۸۰۵٫۵۵ تومان در ساعت** است؛ کارکرد پیوسته ۷۲۰ ساعت حدود **۱٫۳ میلیون تومان** هزینه دارد. این هزینه جدا از برنامه وب است و با قیمت روز یا صورتحساب نهایی ممکن است تفاوت داشته باشد. این اندازه برای شروع و کاتالوگ فعلی انتخاب شده؛ افزایش پلن باید بر اساس اندازه ایندکس، حافظه و تأخیر واقعی انجام شود.

## دسترسی

متغیرهای زیر فقط در تنظیمات سرور نگهداری می‌شوند:

```text
ELASTICSEARCH_URL=http://torob-search-1023:9200
ELASTICSEARCH_INDEX=torob-products
ELASTICSEARCH_USERNAME=torob_reader
ELASTICSEARCH_PASSWORD=<server-only secret>
```

کاربر `torob_reader` فقط مجوزهای `read` و `view_index_metadata` روی کاتالوگ و `monitor` برای وضعیت سرویس دارد. مجوز نوشتن، حذف ایندکس یا مدیریت کاربران ندارد. رمز مدیر Elasticsearch در تنظیمات وب قرار نمی‌گیرد. اتصال بدون احراز هویت از داخل شبکه نیز HTTP 401 برمی‌گرداند.

رمزها وارد Git، فرانت‌اند، artifactهای CI یا خروجی لاگ نمی‌شوند. اتصال HTTP فوق فقط در شبکه خصوصی لیارا انجام می‌شود؛ این نشانی نباید برای دسترسی عمومی به دیتابیس استفاده شود.

## ورود و به‌روزرسانی داده

اسکریپت `scripts/index-elastic.mjs` یک عملیات مدیریتی مستقل است. آن را با دسترسی مدیر، از سرویسی در همان شبکه خصوصی و روی خروجی معتبر `dist/data` اجرا کنید. وب‌سرور یا بازدید کاربر فرایند ورود داده را شروع نمی‌کند.

```sh
node scripts/index-elastic.mjs
```

هر بار یک ایندکس نسخه‌دار تازه ساخته می‌شود. داده‌ها در بسته‌های ۵۰۰ محصولی وارد می‌شوند، تعداد اسناد بررسی می‌شود و سپس alias به شکل اتمیک به ایندکس تازه تغییر می‌کند. اگر ورود داده کامل نشود، alias قبلی باقی می‌ماند. ایندکس‌های قبلی خودکار حذف نمی‌شوند؛ پس از تأیید انتشار و پایان بازه بازگشت، مدیر باید نسخه‌های اضافه را پاک کند تا دیسک پر نشود.

متغیرهای احراز هویت این اجرای مدیریتی باید فقط در محیط همان پردازش باشند. نباید رمز مدیر را جایگزین رمز محدود وب‌سرور کرد. Docker برنامه به‌عمد ابزار ورود مدیریتی را اجرا نمی‌کند؛ برای اجرای یک‌باره می‌توان از shell خصوصی لیارا و اسکریپت موقت استفاده کرد.

## بررسی پس از انتشار

- سلامت کلاستر و تعداد اسناد alias را از شبکه خصوصی بررسی کنید.
- پاسخ جست‌وجوی عمومی باید موتور فعال را Elasticsearch گزارش کند.
- تعداد و صفحه‌بندی نتیجه با داده‌های واقعی کنترل شود.
- پیکربندی مسیریابی و دستیار هوشمند بعد از افزودن متغیرهای ES حفظ شود.
- در قطع Elasticsearch، ایندکس معکوس داخلی باید نتیجه بدهد؛ خطای موتور نباید کل برنامه را از کار بیندازد.

این استقرار یک نود دارد؛ replica و تحمل خرابی چند نود فراهم نمی‌کند. ایندکس از دیتاست رسمی قابل بازسازی است و مسیر جایگزین داخلی برای تداوم جست‌وجو باقی می‌ماند.
