# پوشش کامل فیلدهای دیتاست نسخهٔ ۱۶

واردکننده تمام ستون‌های موجود در سه CSV رسمی را نگه می‌دارد. دادهٔ منتشرنشده یا نامشخص با حدس، مدل زبانی یا اطلاعات ساختگی پر نمی‌شود. کامل بودن انتقال فیلدها به معنی کامل بودن اطلاعات منبع یا تأیید زندهٔ موجودی نیست.

## ساخت و اعتبارسنجی

```sh
python scripts/setup_data.py --archive .data/official-v16.zip
# برای CSVهای استخراج‌شده
python scripts/import_dataset.py .data/csv
python scripts/verify_data.py .data/csv
```

`verify_data.py` تمام محصولات و پیشنهادها را با digest رکورد کامل CSV مقایسه می‌کند؛ مقایسهٔ فروشگاه‌ها مستقیم و شامل تمام فیلدهاست. این بررسی شامل ترتیب و تعداد مشخصات و تصاویر، مدل، توضیح فروشنده، قیمت، زمان تغییر قیمت، گارانتی، دسته‌ها، تماس‌ها، برنامهٔ کاری و شرایط پرداخت است. ارتباط پیشنهاد با محصول و فروشگاه، نبود شناسهٔ تکراری، قیمت حداقل، shard، اطلاعات featured و تمام ردیف‌های Search Index نیز بررسی می‌شوند.

در `meta.json` مقدار `dataSchema: 2`، SHA256 و اندازه و ستون‌های هر CSV در `sourceFiles` و آمار پوشش در `coverage` ثبت می‌شود. واردکننده و verifier هنگام تغییر مجموعهٔ ستون‌های منبع متوقف می‌شوند تا ستون تازه بدون نگاشت از دست نرود. فایل‌های دیتاست در Git نگه‌داری نمی‌شوند؛ CI از آرشیو رسمی با checksum ثابت بازسازی می‌کند.

## نگاشت فیلدها

| منبع | فیلدهای خروجی |
| --- | --- |
| `products.product_id` و `persian_title` | `id` و `title` |
| `products.category_name` و `brand_name` | `category` و `brand` |
| `products.model` | `model` با حفظ متن منبع یا `null` |
| `products.image_urls` | تمام آدرس‌ها در `images` با همان ترتیب؛ `image` همچنان اولین تصویر است |
| `products.specs` | تمام مشخصات در `specs`؛ بدون محدودیت ۱۲ مورد |
| `offers.product_id` | ارتباط پیشنهاد از طریق آرایهٔ `offers` همان محصول |
| `offers.offer_id` و `shop_id` و `seller_title` | `id` و `shop` و `title` |
| `offers.description` | `description`؛ متن منبع یا `null` |
| `offers.price_toman` و `last_price_changed_at` و `warranty` | `price` و `updated` و `warranty` |
| تمام ستون‌های `shops` | با نام اصلی حفظ می‌شوند؛ `category_names` و `contacts` و `payment_options` و `weekly_hours` به صورت JSON واقعی |
| `shops.supports_fast_delivery` | فقط `true` یا `false` یا `null`؛ رشتهٔ `false` به مقدار درست بولی تبدیل می‌شود |

`min` و `shard` از داده‌های منبع محاسبه می‌شوند. aliasهای قبلی API حفظ شده‌اند. برای تماس‌ها، `contactsSynthetic: true` در هر فروشگاه و در meta ثبت شده است؛ شماره‌ها برای تماس واقعی یا پیگیری خودکار قابل استفاده نیستند. اطلاعات دستهٔ فعالیت به معنی داشتن یک محصول مشخص نیست؛ این ارتباط تنها از جدول offers گرفته می‌شود.

ارسال فوری برای ۱٬۱۶۸ فروشگاه `true` و برای ۴۳۳ فروشگاه `false` ثبت شده است. در برنامه‌های کاری ۲۷٬۲۷۰ روز با وضعیت `declared`، تعداد ۴٬۰۰۶ روز `closed` و ۳۵ روز `unsupported` وجود دارد. وضعیت unsupported یا ساعت نامشخص به باز بودن تبدیل نمی‌شود. شیفت مساوی `00:00:00` تا `00:00:00` نیز placeholder است و نشانهٔ فعالیت شبانه‌روزی نیست.

تمام شماره‌های تماس منبع ساختگی‌اند و اغلب نام فروشگاه‌ها نیز جایگزین شده‌اند. مختصات و سایر فیلدهای منبع بدون تولید مقدار تازه حفظ می‌شوند. این نسخه عنوان انگلیسی یا توضیح مستقل محصول را به صورت ستون جدا ندارد؛ هر مقدار موجود در specifications حفظ شده است. موجودی زنده، قیمت امروز، ترافیک زنده و Price History چندنقطه‌ای در این فایل‌ها وجود ندارد؛ زمان آخرین تغییر قیمت به تنهایی نمودار تاریخچه نمی‌سازد. مناطق و محصولات منبع نیز پوشش کامل تهران را ندارند.

## اثر بر حجم

اندازه‌ها برای فایل‌های JSON حاوی Gzip/Base64 روی دیسک اندازه‌گیری شده‌اند و اندازهٔ حافظهٔ JavaScript یا زمان پاسخ شبکه نیستند.

| بخش | قبل | بعد |
| --- | ---: | ---: |
| تمام ۱۳۹ فایل داده | ۷۷٬۶۱۹٬۴۶۵ بایت | ۹۳٬۲۷۲٬۷۸۱ بایت |
| ۱۲۸ shard محصول | ۶۰٬۸۶۷٬۶۳۲ بایت | ۷۵٬۵۹۹٬۸۷۲ بایت |
| فروشگاه‌ها | ۸۸۲٬۷۱۵ بایت | ۱٬۸۰۱٬۸۰۷ بایت |
| محصولات featured | ۵٬۵۲۳ بایت | ۶٬۴۳۹ بایت |

حجم کل حدود ۲۰٫۲ درصد افزایش یافته است. هر هشت فایل Search Index از نظر SHA256 دقیقاً ثابت مانده‌اند؛ شناسه، عنوان، دسته، قیمت حداقل و شمارهٔ shard جست‌وجو تغییر نکرده‌اند. تصاویر به صورت URL حفظ می‌شوند و فایل تصویر در دیتاست بارگیری یا تکثیر نشده است. بزرگ‌ترین shard بازشده در JSON حدود ۹٫۵۵ مگابایت است؛ مصرف حافظهٔ objectهای برنامه باید با smoke test محیط محدود جداگانه سنجیده شود.
