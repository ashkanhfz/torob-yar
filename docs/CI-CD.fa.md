# انتشار خودکار روی لیارا

[وضعیت GitHub Actions](https://github.com/ashkanhfz/torob-yar/actions/workflows/quality.yml)

هر push و pull request ابتدا بررسی نحوی و تست‌های واحد را اجرا می‌کند. سپس آرشیو رسمی v16 با SHA-256 ثابت بررسی می‌شود، داده‌ها از CSV بازسازی می‌شوند و ارتباط ۲۲۵٬۹۰۳ محصول، ۳۳۱٬۵۰۶ آفر و ۶٬۴۷۶ فروشگاه کنترل می‌شود. آرشیو دانلودشده کش می‌شود؛ خروجی importer در هر اجرا دوباره ساخته می‌شود تا تغییرات آن تست شوند.

پس از تست API با دیتاست کامل، تصویر Docker واقعی ساخته و با سقف ۵۱۲ مگابایت حافظه و نیم هسته اجرا می‌شود. بررسی نهایی، صفحهٔ اصلی، جست‌وجو، دریافت مشخصات محصول و بسته‌بودن فایل‌های خصوصی را کنترل می‌کند. این تست‌ها از هوش مصنوعی پولی یا تماس فروشنده استفاده نمی‌کنند.

Snapshot ایندکس داخلی از همان کانتینر تست‌شده برداشته و همراه داده‌ها به job انتشار منتقل می‌شود. تصویر پایهٔ Node با digest ثابت است تا فرمت V8 در ساخت و اجرا یکسان بماند. در ساخت لیارا، snapshot به مسیر خصوصی `/app/.cache` منتقل و پوشهٔ موقت `dist/.build` حذف می‌شود؛ در نتیجه پردازش کامل کاتالوگ روی builder لیارا تکرار نمی‌شود. هر دو مسیر خصوصی در smoke test باید HTTP 404 بدهند. ساخت مستقیم Docker بدون این artifact نیز پشتیبانی می‌شود و snapshot را خودش تولید می‌کند؛ تغییر digest تصویر پایه باید دوباره از همین تست‌ها عبور کند.

فقط اجرای موفق روی `main` اجازهٔ انتشار دارد. job انتشار، خروجی دادهٔ همان اجرای تأییدشده را دریافت می‌کند و با CLI نسخهٔ `9.6.0` روی برنامهٔ موجود `torob-yar-next-1023` منتشر می‌کند. پورت ۳۰۰۰ و دیسک `runtime` از `liara.json` حفظ می‌شوند. در پایان، شناسهٔ commit از `/release.json` با commit این اجرا مقایسه می‌شود و آزمون خواندن API روی سایت عمومی تکرار می‌شود؛ سالم‌بودن نسخهٔ قبلی برای موفق‌شدن انتشار کافی نیست.

در تنظیمات Actions مخزن، secret با نام `LIARA_API_TOKEN` و variable با نام `LIARA_TEAM_ID` تنظیم می‌شوند. برنامه متعلق به تیم است، بنابراین شناسهٔ تیم باید همراه درخواست انتشار ارسال شود. توکن نباید در سورس، فایل workflow یا خروجی فرمان‌ها قرار بگیرد. تنظیمات مدل، رمز ادمین و سایر متغیرهای runtime در خود لیارا باقی می‌مانند. pull request و fork به مرحلهٔ انتشار دسترسی ندارند؛ توکن GitHub فقط مجوز خواندن محتوا دارد و نسخهٔ actionها با commit ثابت مشخص شده است.

انتشارهای تولید هم‌زمان اجرا نمی‌شوند و انتشار فعال با push جدید قطع نمی‌شود. اجرای دستی از صفحهٔ Actions و گزینهٔ **Run workflow** روی `main` نیز تمام مراحل تست و انتشار را تکرار می‌کند. اگر هر مرحلهٔ قبل از انتشار شکست بخورد، نسخهٔ فعلی سایت تغییر نمی‌کند. اگر بررسی پس از انتشار شکست بخورد، اجرای GitHub قرمز می‌شود؛ بازگشت خودکار وجود ندارد و می‌توان از پنل لیارا release قبلی را بازگرداند.

مرجع فرمان انتشار: [مستندات رسمی Liara برای GitHub](https://github.com/liara-cloud/docs/blob/master/src/pages/paas/cicd/github.mdx) و [Liara CLI](https://github.com/liara-cloud/cli).
